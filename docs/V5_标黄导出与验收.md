# Budget Optimizer V5 — 正式预算标黄导出（首版测试）

> **状态：源码已提交，尚未经过公司 Excel 实机验证。** 在 `Budget_Optimizer_V5_Dev.xlsm` 测试，不要修改 `Budget_Optimizer_V4_Stable.xlsm`。

## 目标和口径

新增独立 VBA 模块 [BudgetOptimizer_V5_Export.bas](../src/BudgetOptimizer_V5_Export.bas)，入口宏：`ExportBudgetV5YellowCopy`。

- 以原始 `Budget_Data`（缺失时为 `Sheet1`）**复制生成新的 .xlsx 工作簿**，不直接导出带 4 个 FY helper 列的 `Budget_Trial`。
- 比较原始值与当前 `Budget_Trial` 对应位置：实际发生变化的输入单元格，写入新值并**标黄**；未发生变化的单元格不标黄，恢复原值后不标黄。
- 只比较 X:AQ（Set QTY）、AR:BK（Pcs/Set）、BL:CE（Comp Ratio）、CF:CY（S/P）、CZ:DS（Share），20 个月 × 5 组 = 100 个输入列。
- **DT:DV Actual S/P 不参与调整**。**DW:EP Sales Amt 原始公式不做直接覆盖**，复制后由 Excel 根据新输入计算。
- 原始工作表的其他信息列、合并单元格、格式和公式尽可能照原样保留。新输出统一命名 Sheet1。
- 新增 `Change_Log`：原始行号、原 Excel 单元格、Model、B 列机种键、H40、月份、参数、原值、新值、差额。
- 保存前用户自行选择**新文件名**；禁止覆盖已存在的文件。导出为无 VBA 的 `.xlsx`。

### 重要限制

- 首版为全表导出，包括滚动窗口内的 20 个月；不只限定 27F。未来如果仅要导出 27F 12 个月，须先确定业务规则。
- 导出会使用当前 `Budget_Trial` 的实际值；**执行前先确认你已完成最后一次输入和试算**。本宏不重新生成 Trial。
- 原预算含外部 Excel 链接时，本版宁可**中止导出**，也不假装生成的文件可离线独立计算。以后可以单独设计合法的“断开链接/缓存值”处理方案，避免改变业务公式。
- 仅修改输入组 X:DS，不能保证原始公式没有其他外部计算依赖；Excel 链接预检发现依赖后会中止。
- 黄色的导出差异标记与界面 Target 黄色属于两种不同用途：输出黄色强调真实变更，界面黄色强调可编辑。
- 如果源文件包含宏、外部链接、公式名称或复杂对象，需验收其 `.xlsx` 保存后外观、公式、计算是否完整。

## 安装

1. 在公司电脑备份 `V5_Dev.xlsm`，保留 `V4_Stable.xlsm` 不变。
2. 打开 V5 Dev，Alt+F11 → File → Import File，新增 `BudgetOptimizer_V5_Export.bas`。保留 V4 主模块、V5_UI 模块、ThisWorkbook 事件，不移除。
3. Debug → Compile VBAProject。编译成功无弹窗。
4. 返回 Excel，确认第二页修改 F/G 后 `Budget_Trial` 已更新，两页金额同步。
5. Alt+F8 → `ExportBudgetV5YellowCopy`，确认导出，再选择**一个全新文件名**。
6. 新打开导出 `.xlsx`，查看 `Sheet1` 和 `Change_Log`。

## 验收样例

1. 找一个当前 27F 月份；改变 `Budget_Detail` 的 Pcs/Set 或 S/P；先核实 Trial 自动变化。
2. 导出后，确认只在有效发生差异的具体月度格子标黄；原值和新值与 Change_Log 对应。
3. 检查 `Set QTY` 的 27F 12 个月：导出应为**数值**，不能出现 `#REF!` 或依赖优化工具的链接。
4. 检查 `Sales Amt` 的原始公式仍在，且根据新输入算出的 Sales Amt 与工具 Trial 一致（允许原始文件既有舍入规则造成的预期差别）。
5. 找一个“修改后恢复原始值”的格子：它不应标黄也不应写入 Change_Log。
6. 检查 `Budget_Data`、`Budget_Trial`、`Budget_Overview`、`Edit_Plan`、V4 Stable 均未被导出宏改写。
7. 若存在外部链接，导出会报错并取消；应先调查链接的业务意义，而不是简单破坏公式。

## Budget_Trial A 列 C 标记（V4 主模块追加）

2026-11-23 更新：`BudgetOptimizer_V4.bas` 现在在每次 `RefreshBudgetSheet1Preview` 后，在 `Budget_Trial` 的 A 列按行填入 **Excel 公式**：

- 如果该行 X:AQ、AR:BK、BL:CE、CF:CY、CZ:DS 五个可编辑数据块（20 个月）中有任意实际值与 `Budget_Data` 对应单元格不同，则该行 A 列显示 `C`。
- 如果全部与原值相同，A 列显示空白；把某参数改回原值后自动消除 C。
- 由于使用 Excel 公式，第一页面机种月度 Set QTY（Overview E:P）修改后，`Budget_Trial` A 列标记无需手动运行宏。
- 第二页参数编辑触发 Trial 重建后，将重新安装标记公式。
- 标记只写在临时试算工作表 `Budget_Trial!A`，不会写到原始 `Budget_Data!A` 或导出副本的 A 列；正式导出仍依据逐单元格真实差异进行标黄。
- **注意：会覆盖 Budget_Trial 的 A 列原内容（仅 Trial），建议先确认 A 列没有需要在 Trial 中保留的其他业务用途。** 另外，100 个输入月份的公式比较会增加 Excel 的重算开销。

### 升级与验收

1. 在 `V5_Dev.xlsm` 备份后，移除旧 `BudgetOptimizer_V4` 模块，导入更新后的 `BudgetOptimizer_V4.bas`；保留 `BudgetOptimizer_V5_UI`、`BudgetOptimizer_V5_Export` 和 `ThisWorkbook`。
2. Debug → Compile VBAProject。编译通过后，在宏列表手动执行一次 `RefreshBudgetSheet1Preview` 以重建 Trial 并设置标记公式；已有 Edit_Plan、Overview 月度计划不应该被清空。
3. 检查至少一行原始数据有明确的 Pcs/Set / S/P 差异，Trial 对应 A 行应显示 `C`。
4. 撤回该调整，Trial A 行应显示空白（前提是该行其他参数/月度 Set QTY 也无差异）。
5. 直接在 Overview 的 E:P 改一个 Set QTY，Trial 对应机种的各 H40 行会动态出现或取消 C。


## 外部链接误报定位补丁

若 Excel 的 Data → Workbook Links 灰色，且在 Budget_Data 的公式里搜索 `[` 没有结果，但导出仍提示外部链接：

- 可能是 `src.Copy` **单独复制工作表**时将名称、图表或其他引用变为外部引用；无法仅凭 `LinkSources` 推断原始预算公式存在外链。
- 最新 `BudgetOptimizer_V5_Export.bas` 在复制后分别检查：源工作簿是否已有链接、导出副本中是否有跨工作簿单元格公式、定义名称是否外部化。错误信息会提示复制后的**具体引用类别**和示例。
- 这一版是**定位性修复**，不是允许自动断开链接。遇到未知链接仍中止导出，不会悄悄把预算公式转换成固定值。

安装：在 V5_Dev.xlsm 删除旧 `BudgetOptimizer_V5_Export` 模块，导入最新 .bas；Debug → Compile VBAProject，运行 ExportBudgetV5YellowCopy。若再次中止，请记录完整的新报错，以便确定是否可以仅清理无依赖的名称，或者需要更换导出复制策略。
